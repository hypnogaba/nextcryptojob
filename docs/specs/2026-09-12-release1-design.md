# NextCryptoJob: специфікація першого релізу

Дата: 2026-09-12. Стан: чернетка на затвердження власником.
Джерела рішень: розмова 11.09, документ ідеї («Відбиток кандидата»), план v2.

## 1. Мета і межі

Живий продукт на `nextcryptojob.xyz` і подача на запуску
(14.09–12.10.2026, подати до 11.10).

Три сторони:
- **Кандидат** входить поштою або через Telegram, відповідає на кілька питань,
  підтверджує X, вставляє гаманці, обирає ролі, отримує бал, картку і щоденну
  добірку вакансій. Завжди безкоштовно.
- **Компанія** працює в CRM з кандидатами, які ввімкнули видимість. 100 $ на місяць.
- **Агент компанії** робить усе, що CRM, через REST і MCP; платить ключем API
  в межах підписки або через x402 за запит.

Не входить: будь-яка плата з кандидатів (заборонено законом, розділ 8), вхід
гаманцем, iPhone, показ PnL, оцінка текстів моделлю, бал людей без реєстрації.

## 2. Кандидат

### 2.1 Вхід і акаунт
- C-1. Вхід поштою: людина вводить адресу, отримує 6-значний код (живе 10 хв,
  5 спроб), вводить його. Акаунт створюється одразу.
- C-2. Вхід через Telegram: кнопка «Увійти через Telegram». Акаунт створюється одразу.
- C-3. До акаунта можна додати другий спосіб (пошта до Telegram або навпаки).
- C-4. Канал повідомлень: пошта за замовчуванням, якщо людина ввійшла поштою;
  Telegram, якщо ввійшла через Telegram. Змінюється в налаштуваннях.
- C-5. Акаунт без Telegram повноцінний. Модуль «сиріт» з NextRole не переносимо.

### 2.2 Перший вхід (питання в рамці наміру)
1. «Що шукаєш?» — одне поле своїми словами. Система пропонує 1–3 ролі зі списку,
   людина підтверджує або змінює.
2. «Де?» — віддалено або місто (правило NextRole: місто означає саме це місто).
3. «Зарплата від?» — необов'язково.
4. «Твій X» — нік → код → людина ставить його в біо або в пост → «перевірити».
5. «Твої гаманці» — одне поле, одна чи кілька адрес; тип (EVM чи Solana)
   визначається автоматично.
6. «Ще джерела» (необов'язково) — GitHub, YouTube, сайт, по одному полю.
7. Бал з'являється частинами; далі картка.

### 2.3 Бал і картка
- C-10. Бал 0–100 по кожній обраній ролі; пояснення кожного пункту; поради, як
  підняти; позначка «покриття» (скільки джерел підключено).
- C-11. Кнопка «оскаржити бал»: запит на ручний перегляд у адмінку.
- C-12. Картка: бал ролі, роль, рівень 1–10, візерунок з ніку. Публічна сторінка
  картки без гаманців і посилань. Кнопка «поділитись у X» (intent-посилання).
- C-13. Профіль приватний. Чужий профіль відкрити не можна.

### 2.4 Добірка і видимість
- C-20. Щоденна добірка вакансій (5 на день, як у NextRole) у вибраний канал і
  на сайті, у годину, яку обрала людина.
- C-21. Перемикач «показувати мене компаніям», вимкнений за замовчуванням, з
  поясненням: поки вимкнено, профіль прихований; коли ввімкнено, компанії з
  доступом бачать бал, ролі, рівень.
- C-22. Показ контакту: «лише після мого схвалення» (за замовчуванням) або
  «Telegram-нік одразу». Остаточне рішення за власником.
- C-23. Запит на знайомство приходить у канал людини: компанія, роль, кнопки
  «так» / «ні».
- C-24. «Завантажити мої дані», «видалити акаунт» (каскад).

## 3. Компанія (CRM)
- CO-1. Реєстрація компанії, команда (кілька людей, ролі: власник, учасник).
- CO-2. Підписка 100 $/міс: Stripe (картка) або USDC (переказ щомісяця).
  Агенції: форма заявки, доступ після ручного схвалення.
- CO-3. Пошук серед видимих кандидатів: роль, бал, рівень, мережі, досвід,
  віддалено чи місто. Без фільтрів за віком, статтю, походженням.
- CO-4. Збережені пошуки, сповіщення про нових кандидатів.
- CO-5. Воронка: знайдені → запит надіслано → контакт отримано → співбесіда →
  найнято / відмова. Нотатки, теги, історія дій.
- CO-6. Запит на знайомство; контакт видно після «так» кандидата (або одразу,
  якщо кандидат так обрав).
- CO-7. Вакансії компанії: створення, показ у добірках кандидатів, пост у X-акаунт.
- CO-8. Налаштування, рахунки, ключі API, журнал дій.
- CO-9. Компанія не бачить адрес гаманців і сирих даних джерел; масового
  вивантаження немає.

## 4. Агенти
- AG-1. REST API і MCP-сервер з тими самими діями, що CRM: `search_candidates`,
  `get_candidate` (анонімно до знайомства), `request_intro`, `intro_status`,
  `post_job`, `list_jobs`, `list_pipeline`, `update_stage`.
- AG-2. Доступ: ключ API (у межах підписки) або x402 за запит.
  Ціни x402 (пропозиція): 0,50 $ за пошук/шортлист, 5 $ за знайомство.
- AG-3. Агент кандидата: MCP `search_jobs` (безкоштовно, лише вакансії).
- AG-4. Відповідь кандидата на знайомство: вебхук компанії або опитування.

## 5. Адмінка
- AD-1. Джерела вакансій: стан, остання успішна перевірка, помилки, скільки
  крипто-вакансій дає кожне джерело сьогодні і за тиждень; додати джерело за
  адресою з перевіркою (код NextRole `addSources`/`intake`).
- AD-2. Джерела балу: частка прогалин по кожному джерелу, черга рушія, помилки.
- AD-3. Люди, компанії, заявки агенцій, знайомства, оскарження балу.
- AD-4. Ворота якості: останній прогін еталонного набору.

## 6. Бал

### 6.1 Джерела і що міряємо
| Джерело | Факти | Чим |
|---|---|---|
| X | підписники; відомі акаунти серед підписників; на власних постах: реакції, перегляди, коментарі; частота власних постів | 6551 |
| GitHub | злиті PR у чужі репо, зірки, рев'ю, підписники, коміти; живі репо, репо з сайтом | GraphQL, 1 запит |
| EVM | вік, надіслані транзакції, мережі, обміни за назвою методу | Etherscan (Ethereum, Arbitrum), Blockscout (Base, Optimism) |
| Hyperliquid | угоди, обсяг | публічний API |
| Solana | підписи, обміни | Helius (власний ключ NCJ) |
| YouTube | підписники, перегляди останніх відео, частота | YouTube Data API |
| Сайт | кількість і свіжість текстів | RSS, sitemap |

### 6.2 Правила формули (v3)
- Прогалина джерела (сервіс не відповів, поле не віддав) не рахується в
  знаменнику і ніколи не стає нулем. Має причину.
- Джерело, яке людина не підключила, дає 0 у ролі (крім пари X|YouTube для
  медійних ролей: береться сильніше).
- Без головного джерела роль не рахується: інженер без GitHub, трейдер без
  угод, медійні ролі без X чи YouTube.
- Бал ролі = 90 × основні джерела + 10 × додаткові (запуск, CV).
- Роль обирає людина; система лише підказує.
- Шкала калібрується так, щоб топи галузі були біля 90–100.
- Відоме обмеження: продаж подарованих токенів рахується як обмін.

### 6.3 Ворота якості
- Еталонний набір: 50 людей (16 + 34), ролі й рівні A/B/C/D.
- Формулу не видаємо людям, поки збіг рівня ≥ 80%.
- Прогін після кожної зміни формули; результат в адмінці.
- Прогін з VPS (там живе рушій).

### 6.4 Швидкість
- Ціль: < 30 с на людину. Джерела паралельно, ліміт на хост, великі запити
  (до 10 000 транзакцій за раз), кеш назв методів.
- Оновлення раз на тиждень, рівномірно по днях.

## 7. Архітектура
- Worker (Next.js через OpenNext): сайт, CRM, адмінка, REST, MCP, x402,
  вебхук Telegram, генерація карток.
- D1 `nextcryptojob` (нова) + D1 NextRole (вакансії, джерела; читання й
  додавання джерел через адмінку).
- Рушій балу на VPS: Node 24 + systemd, черга `score_jobs` через D1 REST.
- Пошта: сервіс обирається за перевіркою (розділ 10).
